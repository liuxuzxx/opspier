# OpsPier 0.1.9：Nacos 与 kubectl 交互终端

状态：用户已确认完整交互终端与 Nacos 同版交付；Linux 实现与验证完成。Windows 实机尚未验收，详见验证记录。

## 当前基线与修改范围

当前版本为 0.1.8。已有未完成的 Nacos 后端、连接类型与模型变更，继续保留并完成，不把它们当成已交付能力。0.1.9 包含 Nacos 配置管理、服务/实例修改和 Kubernetes 交互终端。

修改集中于 Nacos 页面和现有未完成模块、Kubernetes 页面、新终端模块、必要命令注册、依赖与版本文件、测试和说明。SSH、数据库、MinIO 既有行为不随本需求重构。公开代码、README 和测试只放通用功能及隔离夹具，不加入公司业务代码、内部地址、真实集群配置或凭据。

## 实现选择

采用应用内 xterm 加本地 PTY 的完整终端，使用用户设备上的 kubectl。复用已有 SSH 终端的输入、尺寸和有界输出设计，新增独立后端，不把 SSH 连接误当本地进程。

只读命令输入框不能覆盖用户已确认的 exec -it 等交互；外部终端窗口不能直接满足工作区内切换需求，因此本版采用内嵌 PTY。具体兼容依赖版本由实施时按官方资料核验并锁定。

## Kubernetes 界面与行为

- Kubernetes 右侧工作区提供紧凑的“资源 / 命令行”切换，正文区域尽量留给数据和终端。
- 初始命令行沿用当前选中的连接、Context 和命名空间。进入终端不会自动连接本机默认集群，也不执行任何 kubectl 业务命令。
- 图形资源页保留现有只读行为；命令行按 kubeconfig 的 RBAC 执行，支持用户主动输入的查询和修改命令，不另加只读命令白名单。
- 支持 `kubectl get`、`describe`、`logs -f`、`get -w`、`exec -it`、命令历史导航、Tab、Ctrl+C、复制粘贴和终端尺寸变化；是否得到结果仍取决于服务端权限。
- 切换显示模式保留终端与当前命令，不重新执行。关闭连接、切换 Context 或退出应用关闭所属本地进程；重新打开只创建新终端，不自动重放命令。
- 终端小状态区显示“默认 Context / namespace”，不宣称能推断用户显式覆盖参数后的每条命令实际目标。

## Context、命名空间与凭据隔离

- 从当前已验证的 kubeconfig 快照中，只取选定 Context 及其引用的 cluster/user，生成该终端专用配置。复用既有认证类型和导入验证，不放宽本版不支持的认证执行插件。
- 证书、私钥和认证数据已由导入过程内嵌，不能把原机相对路径直接交给子进程。
- 使用随机应用私有目录与文件，Unix 权限为 0700/0600，Windows 使用当前用户私有应用目录并验证访问控制；不用固定共享文件名。
- 子进程单独设置 KUBECONFIG，禁止修改宿主进程环境、用户 `~/.kube/config` 或其 current-context。
- 显式选择 namespace 时，下一条默认命令使用该 namespace；正在运行的日志/watch/exec 不被静默改指向。仅原子更新同一集群的私有配置，不往终端注入切换命令。
- 资源页未选 namespace 代表全量查询；kubectl 仍保持自身标准语义，默认 namespace 为 default，跨命名空间由用户显式使用 -A/-n。界面清楚显示这个默认值，不给不支持 -A 的命令强行补参数。
- 切换 Context 必须结束旧 PTY，重新显式打开新 Context 的终端，不能把正在运行的命令悄悄改连其他集群。
- 完整终端允许用户显式指定自己的参数或执行 shell 命令；私有默认配置是会话隔离，不是超出操作系统/RBAC的安全沙箱。界面与说明不得声称所有手输命令始终被锁定在初始集群。
- 不记录终端输入、输出或命令历史到应用诊断日志；关闭 shell 自动落盘历史，避免认证参数留存。配置仅在进程需要期间存在，关闭后清理；异常退出遗留的专用目录下次启动受控清理，不遍历删除其他目录。

## 本地进程与终端模块

- 新增 `kubectl_terminal` 后端管理：open/input/resize/poll/close。每项验证终端 ID、所属 Kubernetes sessionId 及 generation，防止迟到请求作用于新连接。
- 新增本地 PTY 支持，Linux 和 Windows 分别使用兼容平台实现；PTY 启动、读写和等待不阻塞 UI 线程。
- shell 与 kubectl 使用经过检查的可执行路径。缺少 kubectl 时明确显示安装/路径配置入口，不默默下载可执行文件或退回另一集群；路径配置不执行命令拼接。
- 命令是用户交互输入。应用启动 shell 的可执行路径、参数和环境分别传递，不把 Context、namespace 或文件路径拼成 shell 命令。
- 输入、输出和会话数有上限，输出背压与分块消费沿用已有模式；大量输出不能无限累积或拖死 UI。Ctrl+C、窗口 resize 和 EOF 必须实际到达 PTY。
- 每个连接最多一个终端，应用终端总数使用现有终端服务同级限制。异步启动途中关闭或切换 Context，要回收迟到进程。
- 关闭后终止本地进程树，释放 PTY、取消读写任务、清理专用配置。不得只隐藏组件而留下进程；不承诺客户端关闭会删除或终止所有已提交到集群的远程任务。
- 前端新增 Kubernetes 终端组件，复用 xterm 使用方式但不为本功能重构 SSH 组件。

## Nacos 同版范围

继续完成已确认的 Nacos 连接测试与保存、命名空间/Group/Data ID 查询，配置查看、新增、编辑、发布、删除和历史回滚；服务/实例查询、启停、权重、元数据及既有服务属性维护。

写操作显示明确目标并确认，返回后核验实际状态；失败或超时不盲目自动重放。保留连接/查询代次和当前目标校验，拒绝迟到回调覆盖其他连接。注册/注销服务等未另行确认的扩展不随本版自行增加。

Nacos 使用既有系统凭据保存机制，测试只连接自有夹具或明确授权测试环境；不把生产账户、配置内容和地址放入公开仓库。
