# OpsPier 0.1.9 开发与验证

状态：Linux 0.1.9 续开发修复及最终候选验证完成；未提交、推送或发布。

## 功能

- Nacos 2.x：连接及系统凭据保存、配置管理、历史对照/回滚、服务属性和实例启停/权重/元数据修改。写入需确认、预检和读回核验，不自动重放结果不确定的写请求。
- Kubernetes：内嵌完整 kubectl PTY 终端，独立 Context 与私有 kubeconfig，支持日志跟踪、watch、交互 exec、中断和调整尺寸。
- 修复同一 Context 下资源浏览及目录更新误取消命名空间查询、误结束终端的问题；真正切换 Context 或关闭工作区仍会取消旧任务。
- CRD 目录使用小页，遇到大页在原游标有界缩页。保留单页 8 MiB、累计读取 16 MiB、30 秒及数量限制；单项过大或总预算不足时明确说明目录不完整。
- 修复终端输入失败后仍发送后续命令片段的问题：停止当前终端，要求重新打开；旧终端失败不影响新终端。

## 验证边界

- 自动化使用自有回环服务和隔离的 HOME、D-Bus、显示器，不操作真实集群或用户正在运行的应用。
- 原生关窗验证立即清理；驱动强制结束按异常退出验证下一次启动清理遗留私有配置。终端不写 shell 历史。
- Nacos 部分 API 没有服务端原子条件更新能力，保留 README 已说明的预检后并发窗口。
- 本轮沿用已存在的实现与批准计划，不删除接手代码；保留未提交工作，不自动提交或替换用户运行版本。

## 退出验证的实际方式

桌面测试的原生关闭使用隔离显示器上所属窗口的 `WM_DELETE_WINDOW`，并等待应用退出后再清理驱动会话；WebDriver 的浏览窗口关闭和删除会话不作为原生应用退出的替代证据。异常终止则另行验证下次启动清理。

## 本轮决定

- 保留接手时全部实现；在专用 feature 分支续做，未删除既有文件。
- 新修复遵循失败复现后验证通过；旧实现以本轮完整回归核对，不删除重写。
- Windows 平台模块编译通过，完整 Windows 应用与实机未验收。

- 测试与候选制品不替换用户正在运行的版本，不自动提交、推送或发布。


## 续开发：暂停路径的输入完整性

- 已复现：首个输入请求未返回时，命名空间更新或 Context 切换暂停会使已接受的后续输入被清空；恢复后终端仍可输入，shell 中保留残缺命令前缀。
- 修复：区分接收新输入与发送已接受输入。命名空间更新等待已有输入请求及队列发送结束；Context 暂停保留队列，恢复后继续发送。关闭、代次替换及输入失败仍按原有逻辑结束所属终端。
- 新增两项真实 Controller 回归，均先失败再通过；终端测试 12/12，前端全套 104/104；同一独立审查席位复核通过。
- 此处验证的是输入 IPC 与默认配置更新的顺序，不将 IPC 成功解释为 shell 命令已执行完成。
- Rust 128 项、版本一致性、TypeScript/Vite、发布辅助 6 项及 Windows 平台模块交叉编译已复验。Windows 完整应用和实机仍未验收。
- 本轮真实 Nacos 启动曾在数据盘高 I/O 压力下超时。JDK 17 对照亦启动缓慢；相同 JAR 校验和的临时内存盘副本在原 JDK 下约 12 秒完成集成测试。未放宽超时、协议断言或回环绑定约束。
- 修复后候选已完成离线锁定构建、真实 kubectl 协议和完整隔离桌面回归；本轮 57 项 UI、2 项 IPC 检查通过，四项清理证据全部通过。
